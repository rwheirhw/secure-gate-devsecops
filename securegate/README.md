# SecureGate package guide

SecureGate evaluates container scan results and Kubernetes manifests against
policy-as-code, produces deterministic CI decisions, and compares approved
posture baselines for drift. The full scenario guide is in the repository
[README.md](../README.md); this page explains the package layout and the
shortest working paths.

## Quick start

```bash
python -m pip install -e .
securegate inspect k8s/deployment.yaml \
  --policy config/policy-development.yaml
securegate serve --no-open --port 8088
```

Use `securegate assess` for a manifest plus a Trivy JSON report, `evaluate`
for an existing Trivy report, `scan` to invoke Trivy, `baseline` to save an
approved posture, and `drift` to compare current posture with that snapshot.
Exit codes are `0` for no block, `1` for a policy block, and `2` for an
execution or input error.

## Environment baseline policies

Start with one of the checked-in policies:

| Policy | Intended use | Default posture |
|---|---|---|
| `config/policy-development.yaml` | Local feature work | Critical controls block; high findings warn |
| `config/policy-staging.yaml` | Pre-release validation | Critical/high findings block |
| `config/policy-production.yaml` | Release and production | Critical/high findings block; sensitive Kubernetes controls block |

Copy a policy to create a team variant. Keep policy files separate from
generated JSON posture baselines under `baselines/`.

## What the UI displays

The dashboard reads structured JSON generated by the API. Vulnerability
findings include the CVE ID, severity, package, installed/fixed versions,
title, description, status, and Trivy `PrimaryURL`. A valid HTTP(S) URL is
rendered as an external CVE link; hovering the finding ID shows the scanner
description. Unsafe or absent URLs are never made clickable.

## Package map

- `models.py`: findings, decisions, risk, and baseline data structures.
- `parser.py` and `scanners/`: Trivy input and execution.
- `inspectors/`: Kubernetes security inspection.
- `policy/`: YAML/JSON policy evaluation and precedence.
- `baseline.py`: approved posture storage and drift detection.
- `json_reporter.py`: CI/API report serialization.
- `server.py` and `web/`: local REST API and dashboard.
- `cli.py`: command-line entry points.

Run the test suite with `python -m pytest -v`. For API consumers, use
`GET /api/status` as a health check and `POST /api/assess` or
`POST /api/inspect` for evaluations.
